# Домашнее задание 1: персональные top-10 рекомендации

ФИО, датасет и ссылки на него — в [DATA.md](DATA.md). Коротко: Amazon Reviews 2023, категория Video Games (официальная 5-core выборка и метаданные товаров), 814 586 отзывов, 94 762 пользователя, 25 612 товаров, 1999–2023.

## Результаты

Test: 2022-07-01 … 2023-09-02, 8 114 пользователей, 24 019 кандидатов, K = 10. Релевантна покупка с оценкой ≥ 4. Гиперпараметры подобраны на validation (2021-07-01 … 2022-07-01), затем модели переобучены на train + validation.

Главное (подробно — в разделе 8 ноутбука):

* **timeSVD++ с членом для пропущенных данных (AllRank, Steck 2010) — лучший на test** по всем метрикам точности. По парному bootstrap он значимо лучше затухающей популярности (p = 0.002) и FM (p = 0.006).
* **Решает время.** Популярность с полураспадом 60 дней в 4.9 раза точнее популярности за всё время. Модели без времени (iALS, ItemKNN, EASE) уступают ей на 28–41% и рекомендуют товары с медианным «возрастом» ~2 000 дней. Временные компоненты timeSVD++ увеличивают NDCG@10 в 4.4 раза по сравнению с SVD++.
* **Цель обучения timeSVD++ важнее архитектуры.** Обученный только на наблюдаемых оценках, он лучше baseline по RMSE (1.269 против 1.281), но почти бесполезен для top-N. Член для пропущенных данных даёт ×6.5 NDCG@10.
* **Метаданные FM неустойчивы во времени.** На validation они дают +31% NDCG@10, но на test FM только с ID (0.0217) обходит полную модель (0.0189): признаки помогают поймать тренды периода, которые не переносятся на следующий год.
* **Компромисс точности и разнообразия.** ItemKNN и EASE покрывают 35–44% каталога, модели с учётом времени — 0.1–5%.

## Что сделано

Пять моделей реализованы с нуля (numpy / scipy / PyTorch). Готовые реализации рекомендательных алгоритмов и обучаемые модели из библиотек не используются.

| модель | файл | суть |
|---|---|---|
| Item-based kNN | `models/item_knn.py` | асимметричный косинус со сжатием, top-k соседей, давность в профиле пользователя |
| iALS | `models/ials.py` | implicit ALS (Hu et al., 2008), решатель — сопряжённые градиенты (Takács et al., 2011) |
| EASE | `models/ease.py` | замкнутая форма (Steck, 2019), обращение через Холецкого |
| FM | `models/fm.py` | Factorization Machine + BPR; метапризнаки товара, профиль платформ пользователя, возраст и свежая популярность товара в момент события |
| timeSVD++ | `models/time_svdpp.py` | Koren (2009): дрейф смещений и факторов, дневные члены, интервалы времени для товаров; член для пропущенных данных (Steck, 2010) для top-N |

Бейзлайны (`models/baselines.py`): случайный, популярный и популярный с затуханием по времени.

**Протокол** (`utils/split.py`, `utils/evaluation.py`): глобальное временное разбиение. Train — до 2021-07-01, validation — 2021-07-01…2022-07-01, test — 2022-07-01…2023-09-02. Гиперпараметры подбираются на validation (Optuna, основная метрика NDCG@10 выбрана заранее). Затем модели переобучаются на train + validation и один раз оцениваются на test. Кандидаты — все товары из обучающих данных, кроме уже купленных пользователем. Релевантный объект — покупка в периоде с оценкой ≥ 4. Пользователи, кандидаты и правила оценки одинаковы для всех моделей.

## Структура

```
hw1/
DATA.md              ФИО, датасет и ссылки на него
README.md            этот файл
experiments.ipynb    основной ноутбук: данные, EDA, протокол, подбор, сравнение, анализ, выводы
models/              по файлу на модель + base.py (интерфейс, реестр) и sampling.py (общий сэмплер негативов)
utils/               загрузка данных, признаки, временной сплит, метрики, оценка, подбор гиперпараметров
tests/               юнит-тесты: каждая модель сверяется с прямым вычислением своей формулы
results/             таблицы метрик и логи подбора (results/tuning/*.json)
requirements.txt     зависимости (Python 3.12)
pyproject.toml       настройки ruff и pytest
```

## Запуск

```bash
cd hw1
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
# для GPU (Linux, CUDA 12.x): pip install torch==2.14.1 --index-url https://download.pytorch.org/whl/cu126
pytest -q tests
jupyter nbconvert --to notebook --execute --inplace experiments.ipynb --ExecutePreprocessor.timeout=-1
```

Все команды выполняются из `hw1/`. Данные (~116 МБ) скачиваются ноутбуком из первоисточника в `hw1/data/raw/`. В репозиторий они не входят. Все случайные зёрна фиксированы (`SEED = 42`), на CUDA включены детерминированные алгоритмы. При `RUN_SEARCH = False` ноутбук не повторяет подбор, а берёт сохранённые лучшие конфигурации из `results/tuning/`. Сохранённый прогон занял ≈ 1 ч 20 мин на общей A100 40 ГБ.
